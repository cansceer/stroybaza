# Плагин Codex «Стройбаза»

Версия 1.2.3 включает правила, брендбук, канон персонажей, шрифты с лицензиями, логотипы, рекламные SVG и референсы сайта/SMM. Отдельная папка автора не требуется.

## Установка и обновление

```powershell
codex plugin marketplace add cansceer/stroybaza --ref main
codex plugin add stroybaza-design@stroybaza
```

Если marketplace уже добавлен, обновите его снимок и установите текущую версию:

```powershell
codex plugin marketplace upgrade stroybaza
codex plugin add stroybaza-design@stroybaza
codex plugin list --marketplace stroybaza --json
```

Проверьте версию 1.2.3 в списке. Если открытый чат продолжает показывать старую версию навыка, начните новый чат или перезагрузите плагины штатным способом.

## Работа

Назовите тип материала, тему и нужный результат. Навык читает вложенные [правила](skills/stroybaza-project/SKILL.md); открытый рабочий проект может дополнять их своими актуальными инструкциями. Для проекта сайта наличие папок рекламы и SMM не требуется.

Товарный рекламный комплект по умолчанию — 10 JPEG; с персонажами — 7 JPEG по имеющимся утверждённым шаблонам. Три отсутствующих светлых шаблона нельзя выдумывать или заменять товарными.

Figma требует отдельно подключённой интеграции. Нативный редактируемый макет и статичные экспорты выдаются отдельно. Результаты не сохраняются в каталог плагина.

## Длинные пути в Git for Windows

При `Filename too long` задайте настройку только для дочерних команд текущего PowerShell, затем повторите обновление:

```powershell
$gitConfigSlot = if ($env:GIT_CONFIG_COUNT) { [int]$env:GIT_CONFIG_COUNT } else { 0 }
[Environment]::SetEnvironmentVariable("GIT_CONFIG_KEY_$gitConfigSlot", "core.longpaths", "Process")
[Environment]::SetEnvironmentVariable("GIT_CONFIG_VALUE_$gitConfigSlot", "true", "Process")
$env:GIT_CONFIG_COUNT = ($gitConfigSlot + 1).ToString()
codex plugin marketplace upgrade stroybaza
codex plugin add stroybaza-design@stroybaza
```

Эти значения действуют до закрытия PowerShell и не меняют глобальную конфигурацию Git. В репозитории также есть `scripts/install-codex.ps1`: он задаёт эту настройку на время обновления и восстанавливает прежнее окружение в `finally`. Для первой установки у него есть флаг `-RegisterMarketplace`.


## Именованные товарные форматы — 1.2.0

Товарные эталоны сверены с живым каталогом 26.11.2026. Добавлены паспорта металлопроката, утеплителя, листовых материалов, наплавляемой кровли, пенопласта, XPS и строительных смесей. Подвариант определяется по геометрии; подвесы и соединители не превращаются в длинные профили. Снятые/неподтверждённые источники исключены из автоматического выбора. Паспорта, источники и отчёт входят в обе поставки.

## Фотографии статей — 1.2.1

По сверке блога 26.11.2026 уточнено поведение фирменного цвета в фотографии. Первая генерация использует выбранные фотографические примеры и явную группу акцента. Для замечания к цвету применяется локальная коррекция того же мастера с сохранением фактуры, света, объёма и сцены. Плоская версия или лишние окрашенные предметы означают отклонение правки и возврат к мастеру. Логотип и экспорт выполняются после приёмки фотографии. Новые текущие примеры, их источники и диагностический отчёт входят в обе поставки; старые тематические референсы сохранены.

`scripts/article-image-brief.mjs` внутри навыка собирает бриф и проверяет полноту ручной визуальной оценки. Регрессионная проверка из корня репозитория: `node --test scripts/test-article-images.mjs`. Скрипт не оценивает пиксели и не гарантирует качество генератора; каждый результат нужно просматривать.

## Сохранение качества и разбор запросов — 1.2.2

Исправлены три проблемы разбора: отрицание композиции, смешение формата файла с композицией и ложный успешный выбор при неизвестной/несовместимой геометрии SKU. Выбор семейства отделён от выбранного варианта; канистры и вёдра не получают мешок. Несколько явно запрошенных экспортов сохраняются как комплект. Добавлены регрессионные случаи с перестановками, отрицаниями, тарой и неизвестными товарами.

Общий процесс сохраняет лучший мастер и требует точечной правки соответствующего слоя с отклонением ухудшений. Он подключён к обеим поставкам и профильным правилам вместо неограниченного цикла исправлений. Для персонажа разделены идентичность, выбор канонической одежды новой сцены и сохранение комплекта при правке/в серии. SMM собирается послойно; метрики привязаны к мастер-ширине 1080 px, готовый текст и заданный состав выдачи защищены. Исторические 36/33 позиций ФК отделены от проверки полноты новой серии. Работающие цветовые правила отдельных форматов сохраняются; марка из приложенной карточки считается указанной в задаче.

Проверки: `node --test scripts/test-product-profiles.mjs scripts/test-article-images.mjs`, затем `scripts/validate.ps1`, `scripts/test.ps1` и `scripts/build.ps1`. Проверки структуры/разбора не гарантируют качество будущей генерации; фотослой и каждый экспорт по-прежнему принимаются визуально.

## Полные подписи статей и редакционные кадры — 1.2.3

Фотографический мастер отделён от конечного изображения статьи: на каждом внутреннем файле обязательны оригинальные X, СТРОЙБАЗА и город целевого домена. В комплект входят 28 готовых SVG с городами из публичного переключателя сайта; подписи не требуют шрифтов или Python на устройстве участника. Помощник `article-signature.mjs` выбирает подпись, рассчитывает размещение и проверяет полноту ручной приёмки конечного файла. Превью карточек остаются без подписи. Источник сверки и порядок выбора домена находятся внутри правил; Москва не подставляется по умолчанию.

В статьях явно разрешены обычные строители и мастера в профессиональной редакционной фотографии. Для практической серии человек с материалом/действием дополняет конструктивные детали и этапы работ, а не исключается из-за запрета переносить рекламных персонажей. Для двух кадров про профили ГКЛ предусмотрена уместная пара «предметная деталь + строитель с профилем». Число файлов определяется заданием.

Авторская пересборка векторов (не нужна пользователям плагина): `scripts/build-article-signatures.py`, зависимость fonttools. Режим `--check` проверяет детерминированность без записи; установленные участники используют готовые SVG. Оригинальные пути X/словесного логотипа сохранены, города Montserrat 400 переведены в кривые.

Полный запрос «изучи, исправь и замени картинку на странице» распознаётся как диагностика, подготовка и публикация точечной замены. Для нового участника без доступа к домену API-токен/подключение запрашивается первым шагом, до генерации. Наличие плагина не передаёт доступ автора. Исходник и снимок страницы сохраняются, загружается новый ресурс, обновляется выбранный экземпляр, чужие изменения и другие страницы/домены не затрагиваются; результат проверяется на публичной странице. `article-repair-plan.mjs` проверяет порядок и область, а реальная публикация требует инструмента/API и доступа участника. Токены и личные хранилища в пакет не входят.
