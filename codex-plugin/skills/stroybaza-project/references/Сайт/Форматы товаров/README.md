# Именованные форматы товарных изображений

Версия 2026-11-26.1. Здесь «формат» означает композицию и способ показа товара. Тип файла и размер экспорта задаются отдельно: прозрачный WebP 1000×1000, меньше 300000 байт.

## Как понимать запрос

«Подготовь изображения для раздела Профили для ГКЛ по формату металлопроката» означает: товарные изображения каталога; состав товаров и геометрия из раздела профилей; композиция из паспорта «Металлопрокат». Маркировка, сечение, толщина стенки, перфорация и фактура остаются от каждого SKU. Нельзя заменить профиль трубой, швеллером или товаром-референсом.

Фразы «по формату», «в формате», «по композиции», «как у» и «в стиле» с именем семейства выбирают явный формат. «Формат WebP/PNG/JPEG» задаёт экспорт, а не композицию. Читай [реестр](profiles.json) и нужный паспорт, затем соответствующую запись [каталога источников](../Референсы/Изображения%20товаров/catalog-index.json).

Порядок: явный формат пользователя → стандарт точной подкатегории → подвариант по геометрии SKU → актуальный карточный образец для неподдерживаемого типа. Корневая категория «Листовые материалы» не делает подвес или профиль ГКЛ плоским листом. «Утеплитель» не объединяет ППС, XPS и битумные рулоны в одну постановку. Если явно названный формат неизвестен или подходят два семейства, уточни только формат; не выбирай произвольный похожий.

Для формального разбора при доступном Node.js используй `scripts/resolve-product-profile.mjs --request "..."` внутри навыка. Можно передать `--category` и `--geometry` для точного SKU. Скрипт не генерирует картинку: он отдельно определяет семейство, геометрию и экспорт. Отрицание формата исключает его; противоречивый или нераспознанный выбор требует уточнить только зависимый параметр. «PNG и WebP» — явно заданный комплект экспорта, «PNG или WebP» — альтернативы, требующие выбора. Формат исходника не считать требованием экспорта.

Статусы помощника:

- `family-selected`: выбрано семейство для раздела; геометрию каждого SKU ещё нужно определить.
- `geometry-required`: передан товар, но его геометрия не установлена; не назначать единственный шаблон по умолчанию.
- `sku-reference-required`: известный тип несовместим с вариантами семейства; нужен его предметный образец.
- `resolved`: совместимый вариант определён; открыть паспорт и источник точного SKU перед созданием. Это не оценка качества готовой картинки.
- `unknown-format`, `ambiguous-format`, `format-clarification-required`: не выбирать случайный или отрицаемый формат.
- `ambiguous-export`: композиция сохраняется, требуется определить только экспорт.

`variants` содержит выбранные варианты только при завершённом выборе. `candidateVariants` — справочные кандидаты для классификации, их нельзя выдавать за выбор конкретного SKU. При нескольких явно запрошенных экспортах `output.exports` задаёт каждый формат отдельно; не читать `output.format: null` как разрешение вернуться к WebP. PDF/SVG помечаются `requiresAdaptation`: они не становятся прозрачным растровым WebP автоматически.

Помощник поддерживает проверенные конструкции запроса, а не все варианты естественного языка. Сверь его результат со смыслом задания перед применением. Если разбор противоречит явному требованию, не следуй ошибочному выводу: используй профильные правила и точные параметры либо выясни только остающуюся неопределённость.

## Перенос между разделами

1. Получи фактические товары из нужной категории без неполных фильтров по марке. Сохрани карту SKU → визуальный вариант; одинаковое видимое исполнение может разделять один файл. Не объявляй выборку полной по первой странице каталога.
2. Классифицируй геометрию каждого SKU. У профилей ГКЛ ПН/ПС/ПП — длинные открытые профили; подвесы, крабы и соединители — компактные детали. Для длинных изделий по запросу металлопроката выбирай `open-profiles`. Компактные детали не растягивай в длинномер: используй их актуальный предметный образец и обозначь исключение. Отсутствующий точный шаблон запроси только для зависимых от него позиций, продолжая независимую часть.
3. Передай пользователю краткий план: раздел, выбранное семейство и версию, подварианты и исключения, источники товаров и состав выдачи. Понятный запрос не требует повторного подтверждения формата.
4. Переноси ракурс, ориентацию, масштаб видимого контура, отступы, перекрытия и разрешённый нижний кроп. Сохраняй реальные размеры и конструкцию SKU. Отдельный срез/повтор предмета используй только по совместимому эталону. Количество повторов в композиции не означает набор в продаже.
5. Сверяй финальный экспорт по тому же паспорту. Измеряй основной контур по порогу alpha>8, проверяй непрозрачную часть и глазами на светлой/тёмной подложке. Нативные артефакты сайта (ореол, почти прозрачный мусор, высота 1001 px) не становятся требованиями нового экспорта.

## Актуальность и приоритет

Паспорта опираются на текущие опубликованные изображения, проверенные 26.11.2026. Старые «три плоских прямоугольника», горизонтальная упаковка Knauf и малый целый рулон больше не являются актуальными композициями соответствующих семейств. Прежний чертёж Knauf y=105 заменён измерением текущего Knauf MINI y≈210; y=105 остаётся у проверенного мешка UNIS, а не у всех упаковок.

Прямое задание пользователя имеет приоритет. Новое явно согласованное изменение может переопределить паспорт; дату изменения фиксируй в новом выпуске. Старый локальный файл, дата его копирования или личная память участника не подтверждают новое согласование. При существенном расхождении с живым сайтом проверь источник и сообщи о нём.

Активные статусы каталога: `site-current`, `visually-current`. `product-source-only` означает источник формы/маркировки, но не готовый эталон композиции или прозрачности. `retired-unavailable` и `unverified-source` исключены из автоматического выбора. Их исторические файлы перенесены в архив. Не находи эталон простым поиском первой картинки в папке.

Перед новой большой серией проверь доступность и актуальность использованных карточек. При доступном Node.js: `scripts/check-product-reference.mjs --id catalog-...`. Изменение контрольной суммы требует сравнения, а не автоматического признания нового шаблона. Недоступный сайт не подтверждает актуальность: явно укажи дату последней сверки и продолжай только работу, не зависящую от отсутствующих данных.
