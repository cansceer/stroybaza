# Подпись изображений статей: логотип и город

Редакция 26.11.2026 по прямому замечанию пользователя. Основной пример — [статья в Калуге](https://stroybaza-kaluga.ru/blog/sploshnoe-ograzhdenie-ili-lyogkiy-zabor-chto-vybrat-dlya-chastnogo-uch/); пользователь также приложил пример подписи «Москва».

Также просмотрены все пять внутренних изображений [второй статьи пользователя о кровельном материале](https://stroybaza-kaluga.ru/blog/pochemu-krovelnyy-material-nelzya-vybirat-tolko-po-vneshnemu-vidu/): полный блок и город повторяются в серии. При заимствовании референса не копировать его подпись автоматически на другой домен.

## Мастер и финал — разные этапы

Запрет генерировать логотип относится к генерации **чистого фотографического мастера**. Он не отменяет обязательную подпись в конечных изображениях внутри статьи. Фото без подписи — промежуточный мастер, не готовая внутренняя иллюстрация. Принимать фотографию и принимать конечный WebP нужно отдельно.

- На каждом изображении **внутри статьи**, включая первое, справа снизу должна быть полная подпись: оригинальный X, оригинальное словесное «СТРОЙБАЗА», ниже — город целевого домена.
- На **превью карточки блога** подписи нет. Это подтверждено отдельно открытой обложкой той же калужской статьи; не переносить правило превью на внутренние изображения.
- Один маленький X без словесного логотипа и города не является полной подписью. Прежний `logo-article.svg` сохраняется как исходная геометрия X и для исторических референсов, а не как готовая новая подпись.

## Город по домену

До финального монтажа определить целевой домен из задания, URL статьи или однозначного контекста. Использовать [реестр подписей](../Референсы/Статьи/Подписи/signatures.json) и соответствующий готовый SVG. В него входят 28 соответствий из публичного городского переключателя сайта, проверенного 26.11.2026. Не все городские статьи имеют один URL или одинаковый состав страниц.

- `stroybaza-kaluga.ru` → `Калуга`; `stroybaza-moscow.ru` → `Москва`.
- `stroybaza-tveri.ru` → `Тверь`; `stroybaza-nizhny.ru` → `Нижний Новгород`; `stroybazaufa.ru` → `Уфа`.
- Не ставить «Москва» по умолчанию, по скриншоту-примеру или по личному городу автора. Не получать название города механической транслитерацией домена.
- Если домен пока не определён, можно продолжать независимую подготовку фотографий; конечный экспорт с подписью не завершать до определения города. Неизвестный домен не подменять похожим: проверить нужный город и добавить подтверждённое соответствие.
- Для нескольких доменов сохранять общий чистый мастер и делать отдельные конечные экспорты с соответствующей подписью. Не перегенерировать фотографию из-за замены города.

## Оригинальные ресурсы и размещение

Готовые SVG содержат неизменённые пути исходного X и словесного логотипа. Город набран Montserrat Regular 400 и переведён в кривые; установленному плагину не нужны Python, дополнительные библиотеки или установка шрифта для отображения подписи. Подпись нельзя поручать генератору изображений или заменять текстом похожего шрифта. Полная подпись накладывается редактором отдельным слоем после приёмки фотографии и окончательного кадрирования.

В проверенных внутренних изображениях 1536×1024 px подпись занимает примерно 170×170 px, отступы справа и снизу — около 68 px; общая непрозрачность — 80%. Геометрия подписи близка к квадрату. Для стартовой калибровки других разрешений: `размер = round(min(width,height)/6)`, отступ справа/снизу `round(min(width,height)/15)`. Вектор сохраняет пропорции, отдельные части не растягиваются.

Это масштабирование подписи по новому примеру, не отмена профильных размеров изображений статьи. Для коротких/малых кадров обязательно проверить читаемость города и баланс по подходящему референсу; числовая формула не заменяет просмотр. Не перекрывать подписью лицо, руку, сечение профиля или другое значимое место. При постановке можно оставить в правом нижнем углу спокойную естественную область, без нарисованной плашки. Сохранять контраст, не затемнять весь кадр ради логотипа.

Если на исходнике уже есть чужой город/знак, вернуться к чистому мастеру. Не накладывать второй логотип поверх первого и не заклеивать подпись прямоугольником. После замены подписи фотографию не перегенерировать.

## Проверка конечного файла

В каталоге навыка доступен `scripts/article-signature.mjs`. План размещения:

```json
{"role":"body","domain":"https://stroybaza-kaluga.ru/blog/","width":1536,"height":1024}
```

Запуск: `node scripts/article-signature.mjs plan.json`. Результат указывает нужный SVG, город, непрозрачность и координаты. Скрипт сам не редактирует фотографию.

После монтажа открыть именно конечный WebP и проверить весь блок, его город, расположение, контраст и отсутствие двойного знака. Для каждого файла отдельно заполнить ручную оценку:

```json
{
  "role":"body",
  "domain":"stroybaza-kaluga.ru",
  "signaturePresent":true,
  "originalAssetUsed":true,
  "cityLabel":"Калуга",
  "signatureVisible":true,
  "placementChecked":true,
  "finalFileChecked":true
}
```

`node scripts/article-signature.mjs --review review.json` отклоняет неполную оценку, отсутствующую подпись и город другого домена. Это проверка полноты ручного просмотра, не автоматическое распознавание пикселей. Для превью проверять `role: "preview"`, `signaturePresent: false`, `finalFileChecked: true`. Принятие фотографического мастера в `article-image-brief.mjs` не заменяет эту финальную проверку.
