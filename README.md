# Stroybaza Design

Плагин Codex и навык ChatGPT для проекта «Стройбаза»: сайт, реклама, персонажи и SMM. Обе поставки содержат правила, брендбук, референсы, SVG, шрифты и лицензии. Отдельная папка автора для начала работы не нужна.

## Структура и источник истины

- `chatgpt-skill/references/` — единая редактируемая библиотека правил и ресурсов.
- `codex-plugin/` — устанавливаемый пакет Codex; библиотека копируется внутрь навыка штатным скриптом.
- `chatgpt-skill/SKILL.md` и `codex-plugin/skills/stroybaza-project/SKILL.md` — инструкции для соответствующей среды.
- `scripts/sync-resources.ps1` — синхронизирует ресурсы; не удаляет лишние файлы автоматически.
- `scripts/validate.ps1` — проверяет манифесты, ссылки, обязательные ресурсы, размеры рекламных SVG и совпадение библиотек по SHA-256.
- `scripts/test.ps1` — проверяет обнаружение дефектов и безопасный импорт на отдельной тестовой копии.
- `scripts/build.ps1` — после проверок собирает оба ZIP, проверяет состав и лимит 25 МБ каждого архива. Существующие архивы не перезаписываются.

Публичная версия хранится в `main`. Рабочая папка пользователя может дополнять опубликованные правила; при конфликте учитываются прямые требования и дата согласования. Для задач сайта не требуется наличие всех направлений проекта.

## Разработка и выпуск

Нужны Git, PowerShell 7+ и Node.js 18+ для проверки и выбора товарных форматов. На Windows при длинных путях включите для своего checkout `git config core.longpaths true`; при новом клонировании можно использовать `git -c core.longpaths=true clone https://github.com/cansceer/stroybaza.git`.

1. Отредактируйте общую библиотеку `chatgpt-skill/references/` и применимые инструкции среды.
2. Повышайте версию **обоих** манифестов Codex при изменении устанавливаемого пакета: кэш установленного плагина нельзя править вручную.
3. Запустите:

   ```powershell
   ./scripts/sync-resources.ps1
   ./scripts/validate.ps1
   ./scripts/test.ps1 -ScratchDirectory "D:/codex-temp/stroybaza-checks"
   ./scripts/build.ps1 -OutputDirectory "D:/codex-temp/stroybaza-build-1.2.0"
   ```

   Выберите доступные временные каталоги своего устройства. Тесты создают отдельную подпапку, ничего не удаляют и сообщают путь. Не помещайте временные данные в пакет.
4. Проверьте `git diff`, создайте коммит и отправьте его в `main`. ZIP не коммитятся: `stroybaza-design.zip` предназначен для ChatGPT, `stroybaza-codex-plugin.zip` — самостоятельный пакет Codex.

## Импорт из отдельного рабочего проекта

Импорт читает только известные ветки инструкций, дизайн-кода, ресурсов и референсов. Отсутствующие направления сохраняются из репозитория. Папки `Рабочие`, `Готовое`, журналы и история загрузок не импортируются.

```powershell
./scripts/import-from-project.ps1 -ProjectRoot "D:/путь/к/stroybaza"
./scripts/import-from-project.ps1 -ProjectRoot "D:/путь/к/stroybaza" -Apply -WhatIf
./scripts/import-from-project.ps1 -ProjectRoot "D:/путь/к/stroybaza" -Apply
```

Без `-Apply` выводится только план. С `-Apply` сначала готовится staging и выполняются все проверки; только затем пакеты заменяются переименованием на одном томе. Предыдущая поставка остаётся в `.import-backups/`, незавершённый staging — в `.import-work/`. Они исключены из Git. Ничего не удаляется автоматически. При ошибке замены выполняется возврат сохранённых пакетов. Ссылки и junction не обходятся. Не включайте в публичный импорт личные данные, рабочие журналы и материалы без разрешения на публикацию.

## Рекламные комплекты

Товарный комплект — 10 JPEG (пять размеров × два фона). С персонажами доступны 7 JPEG: пять тёмных и два светлых (1080 × 607, 1000 × 1000). Отсутствующие три светлых шаблона нельзя выдумывать или заменять товарными. Для явно запрошенных десяти персонажных вариантов указывается недостающая часть; семь файлов не называются десятью. Состав закреплён в `references/Реклама/Ресурсы/variants.json` обеих поставок.

Правила листовой серии включают y=208, три листа со скрытыми нижними торцами и согласованный масштаб среза; приложен утверждённый образец ОСБ 12 мм. Старые каталожные примеры не заменяют этот эталон.

## Установка и обновление Codex

```powershell
codex plugin marketplace add cansceer/stroybaza --ref main
codex plugin add stroybaza-design@stroybaza
```

Для уже добавленного marketplace:

```powershell
codex plugin marketplace upgrade stroybaza
codex plugin add stroybaza-design@stroybaza
codex plugin list --marketplace stroybaza --json
```

Проверьте текущую версию в списке. Если открытый чат показывает старые инструкции, начните новый чат или перезагрузите плагины штатным способом. [Описание установленного пакета](codex-plugin/README.md).

Для нативного редактируемого Figma-документа нужна отдельно доступная Figma-интеграция. Сам плагин не подключает её и не выдаёт плоский экспорт за редактируемый исходник.

### Установка на Windows с длинными путями

При работе из checkout рекомендуется `./scripts/install-codex.ps1` (при первой установке — `-RegisterMarketplace`). Скрипт временно передаёт дочернему Git `core.longpaths=true` через окружение, сохраняет ранее заданные настройки, обновляет и проверяет плагин, затем восстанавливает окружение. Глобальные настройки Git не меняются. Для нового checkout используйте указанное выше `git -c core.longpaths=true clone ...`. Способ без checkout описан в `codex-plugin/README.md`.


## Именованные товарные форматы — 1.2.0

Товарные эталоны сверены с живым каталогом 26.11.2026. Добавлены паспорта металлопроката, утеплителя, листовых материалов, наплавляемой кровли, пенопласта, XPS и строительных смесей. Запрос «Подготовь изображения для раздела Профили для ГКЛ по формату металлопроката» выбирает товарный раздел отдельно от композиции. Подвариант определяется по геометрии; подвесы и соединители не превращаются в длинные профили. Снятые/неподтверждённые источники исключены из автоматического выбора. Паспорта, источники и отчёт входят в обе поставки.

Проверка выбора форматов: `node --test ./scripts/test-product-profiles.mjs`. Внутри обеих поставок доступны `scripts/resolve-product-profile.mjs` для выбора композиции и `scripts/check-product-reference.mjs` для повторной сверки источника. Проверка сайта выполняет только чтение; смена хеша требует сравнения изображений.
