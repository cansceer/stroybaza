# Фотографии статей

[Паспорта примеров](articles.json) содержат текущие источники, SHA-256 вложенных файлов, поверхности акцента и признаки, которые надо сохранить. Перед генерацией открыть 2–3 изображения. Вложенные примеры позволяют работать без личной папки автора и без доступа к сайту.

- `wet-coating`: влажный слой и отражения, широкая область акцента; маленькая обложка служит только визуальным примером.
- `metal-lintel`: металл, грани, стыки и естественные блики.
- `foundation-insulation`: матовый материал, торцы, фактура и контактные тени.
- `floor-reflections`: целый пол под разным освещением; исходный SVG не переносить генерацией.

Изображения с сайта являются примерами обработки. Они не определяют новый сюжет, размер итогового файла или технологию строительных работ. Старые тематические обложки сохранены в соседней папке «Превью статей».

## Бриф и визуальная проверка

Из каталога навыка (где находится SKILL.md):

```sh
node scripts/article-image-brief.mjs brief.json
node scripts/article-image-brief.mjs --review review.json
```

Пример `brief.json` для коррекции удачного кадра:

```json
{
  "mode": "color-correct",
  "role": "preview",
  "scene": "Рабочий укладывает плиты утеплителя у фундамента",
  "baseImage": "/work/article/best-photo.png",
  "accent": {
    "group": "Плиты утеплителя",
    "surfaces": ["верхние поверхности и торцы уже видимых плит"],
    "reason": "Материал, о котором рассказывает статья"
  },
  "referenceIds": ["foundation-insulation", "metal-lintel"]
}
```

Для первой генерации указать `mode: "generate"`, убрать `baseImage`, описать нужную сцену. `role` — `preview` или `body`. `baseImage` в коррекции всегда указывает на лучший реалистичный мастер. Файл надо открыть и передать редактору; скрипт не загружает изображения и не проверяет пиксели. При отсутствии Node заполнить тот же бриф вручную.

После правки человек/агент визуально сравнивает два изображения, затем заполняет `review.json`:

```json
{
  "sameScene": true,
  "photorealistic": true,
  "volumePreserved": true,
  "texturePreserved": true,
  "lightingPreserved": true,
  "accentScopePreserved": true,
  "skinNeutral": true,
  "targetHueSuitable": true
}
```

Только восемь явных положительных оценок допускают принятие. Любой провал означает возврат к лучшему мастеру. Пропущенная оценка не считается положительной. Это контроль полноты ручной проверки, а не автоматическая оценка фотографии. Подробный порядок — в инструкции «Фотографии статей — генерация и коррекция цвета».

## Обязательная подпись и люди

Удачный мастер и его положительная цветовая оценка — промежуточные результаты. Внутренние изображения получают полную подпись X + СТРОЙБАЗА + город целевого домена из [реестра](Подписи/signatures.json), затем проверяются отдельно через `article-signature.mjs --review`. Превью карточки без подписи. Домен можно передать в бриф как `domain`; если его нет, фотография разрешена, но финальный экспорт ждёт определения города. Полный порядок — в [правилах подписи](../../Инструкции/Подпись%20изображений%20статей.md).

Для нового кадра с обычным строителем можно передать `humanAction`, например «строитель держит профиль ПС и показывает его сечение». Фирменные персонажи бренда не обязательны. `humanAction` не используется при локальной коррекции цвета — добавление человека меняет сюжет и требует отдельного задания. В серии сочетать профессиональные кадры людей с предметными деталями и этапами работ; две одинаковые раскладки не заменяют разнообразие сцены.
